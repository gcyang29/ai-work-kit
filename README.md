# AI Work Kit — Cofa Probe 실무형 과제 대응 가이드

> 공개 재사용 지침입니다. 실제 시험 문제, 입력 데이터, 답안, 개인 정보 또는 제출 결과물을 포함하지 않습니다.

## 목적

Codex CLI가 낯선 실무 과제를 **분석 → 계획 → 구현 → 검증 → 제출 점검** 순서로 지원하도록 하는 범용 가이드입니다. 목표는 긴 프롬프트 암기가 아니라, 요구사항을 빠뜨리지 않고 **실제로 작동하며 설명할 수 있는 결과물**을 만드는 것입니다.

## 가장 중요한 규칙

1. **실제 과제 README, 제출 규정, 플랫폼 운영 지침이 이 문서보다 우선**합니다. 충돌하면 이 지침을 적용하지 않습니다.
2. 과제의 정답이나 구현 방식을 미리 가정하지 않습니다. 웹사이트뿐 아니라 데이터 분석, 문서 처리, 자동화 등 과제에 적합한 산출물을 선택합니다.
3. 입력 자료와 담당자 답변에서 확인한 사실, 가정, 미확인 사항을 구분합니다. 불확실한 핵심 조건은 업무 담당자에게 질문할 내용을 제안합니다.
4. AI는 코드 작성, 실행, 테스트, 오류 수정에 사용할 수 있지만 **요구사항 우선순위와 최종 승인, 주요 결과 확인은 응시자**가 수행합니다.
5. 없는 테스트 결과나 성과 수치를 만들지 않습니다. **미구현 / 미검증 / 실패**를 솔직하게 표시합니다.
6. 시험 문제, 제공 파일, 결과물, 작업 기록을 외부로 보내거나 Git Push하지 않습니다. 금지된 서비스 연결, 감독 우회, 보안 설정 변경, Computer Use를 사용하지 않습니다. 외부 공개 자료 활용은 시험 규정과 과제별 허용 범위만 따릅니다.
7. 제출 확정 후의 **후속 서술형은 AI를 사용하지 않고 응시자가 직접 작성**합니다. 이 가이드는 과제 풀이 단계에만 사용합니다.

## 5단계 실전 흐름

| 단계 | 사용자가 확인할 것 | Codex에 맡길 것 | 완료 기준 |
|---|---|---|---|
| 1. 분석 | 과제 목표, 필수 제출물, 우선순위 | README/파일 구조 파악, 요구사항/불명확한 점 정리 | 필수 요구사항과 질문 목록 확보 |
| 2. 계획 | 범위, 시간, 기술 선택 승인 | 작은 실행 가능 버전과 단계별 계획 제안 | 각 단계의 확인 방법 정의 |
| 3. 구현 | 실제 기능과 동작 확인 | 핵심 기능 구현, 실행, 오류 수정 | 핵심 경로가 실제 작동 |
| 4. 검증 | 기대 결과와 실제 결과 비교 | 테스트, 경계값/예외 확인, 회귀 테스트 | 요구사항별 증거와 미해결 항목 확보 |
| 5. 제출 | 필수 파일, 저장 상태, 확정 버튼 | 제출 요건 대조, 설명용 핵심 판단 정리 | 파일 누락 없음, 이해한 내용만 제출 |

### 1. 분석 — 첫 입력 예시

```text
현재 실제 과제 README와 작업 폴더의 파일을 읽어줘.
필수 요구사항, 제출 파일과 경로, 입력 데이터, 제한 조건을 표로 정리해줘.
확인된 사실/추측/담당자 확인 필요 사항을 나눠줘.
구현 방향을 바꿀 수 있는 질문을 최대 5개 제안해줘.
아직 코드는 수정하지 마.
```

### 2. 계획 — 두 번째 입력 예시

```text
확인된 요구사항과 담당자 답변을 기준으로 제한시간 내 실행 가능한 계획을 세워줘.
필수 기능 우선으로 3~5단계로 나누고, 각 단계의 완료 기준과 테스트 방법을 적어줘.
선택이 필요한 주요 대안은 장단점과 추천 이유를 제시해줘.
내 승인 전 대규모 구현을 시작하지 마.
```

### 3. 구현 — 단계별 입력 예시

```text
승인된 계획의 다음 단계만 구현해줘.
기존에 동작하는 기능은 유지하고, 필요한 파일만 수정해줘.
실행 가능한 상태까지 작업한 뒤 실행 방법, 수정 파일, 확인한 결과, 미완료 항목을 알려줘.
실제로 실행하지 못했다면 못했다고 표시해줘.
```

### 4. 검증 — 단계별 입력 예시

```text
실제 과제 README의 요구사항별로 검증 표를 만들어줘.
정상 입력, 빈 입력, 잘못된 입력, 경계 상황, 핵심 기능 간 영향까지 가능한 범위에서 확인해줘.
실패한 경우 원인을 파악해 수정하고 관련 테스트를 다시 실행해줘.
각 항목을 통과/실패/미검증으로 구분하고 근거를 남겨줘.
테스트 통과를 위해 원래 요구사항을 임의로 완화하지 마.
```

### 5. 제출 — 최종 입력 예시

```text
새 기능을 추가하지 말고 제출 점검만 해줘.
실제 과제 README에 지정된 필수 파일명, 경로, 저장/실행 상태, 누락 사항을 확인해줘.
실제 수행한 핵심 판단 3가지, 테스트 결과, 알려진 한계를 짧게 요약해줘.
과제 풀이 단계까지만 도와주고, 후속 서술형 답안을 대신 만들거나 제출하지 마.
```

## 시간 운영 예시 (과제 풀이 최대 180분인 경우)

- 0–20분: 과제/파일 분석 및 업무 질문
- 20–40분: 구현 범위와 계획 결정
- 40–125분: 필수 기능 구현 및 중간 실행
- 125–165분: 검증, 오류 수정, 제출물 정리
- 165–180분: 저장·필수 파일 점검, 제출 절차 (안내서상 종료 최소 10분 전 제출 시작 권장)

이는 **연습용 권장 배분**이며 실제 과제 난이도에 따라 조정합니다. 후속 서술형 대기 및 답변까지 전체 시험 종료 시각을 준수합니다.

## 모델과 설정

- 처음에는 **허용된 모델 중 익숙한 하나**로 시작하고, 정확한 이유가 있을 때만 전환합니다. 예: 6.1 Sol + Medium은 연습용 시작 조합이며 공식 최적 조합은 아닙니다.
- 복잡한 설계/반복 오류는 더 높은 추론 수준을 고려하고, 단순 수정은 기본 수준을 유지합니다. 무조건 High/Fast가 더 좋지는 않습니다.
- Codex의 `/status`, `/model` 및 실제 제공 메뉴로 설정을 확인합니다. **버전 업데이트 금지**, Astra 등 제한 모델과 외부 AI 연결 금지.
- 기본 승인 설정을 유지하고 요청된 권한의 범위를 검토합니다. Full Access나 설정 변경으로 플랫폼 제한을 우회하지 않습니다.

## 공개 GitHub 저장소에서 가져오기

```bash
git clone https://github.com/gcyang29/ai-work-kit.git
```

그다음 Codex에 `클론한 저장소의 범용 지침을 읽고 실제 과제 README를 우선해 참고해줘`라고 요청합니다. **Clone만으로 별도 Skill이 자동 활성화된다고 가정하지 마세요.** 시험 환경에서 인식하지 못하면 `SKILL.md`를 직접 읽도록 요청해도 범용 작업 지침으로 사용할 수 있습니다. 가져온 저장소의 문서를 과제의 필수 `README.md`로 덮어쓰지 마세요.

## 참고 및 면책

공식 시험 가이드에 명시된 주요 사실: 과제 수행 최대 180분, 후속 서술형 6문항(각 5분), 개인 PC 파일 업로드 제한, 공개 Git Clone 허용(세부 규정 준수), 결과물 외부 전송 및 Git Push 금지, 후속 서술형 AI 금지. **이 저장소는 참가자 개인의 범용 가이드이며 대회 공식 자료나 사전 작성된 답안이 아닙니다.**
